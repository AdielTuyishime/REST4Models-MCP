Overview

Summary

  • A lightweight dynamic tool to provisioning RESTful services for model management
  • REST APIs are provided on-the-fly for any model and metamodel
  • Following REST principles, the tool ensures a stateless and scalable service

What it does

Turns models into RESTful services. The tool loads Ecore metamodels and models and exposes REST APIs to:

  • Discover metamodels and available models in the repository
  • Read models as JSON or XML
  • Perform CRUD operations on metamodels and models
  • Enable interoperability with external tools

Capabilities

Model Discovery & Browsing read

  • List metamodel packages and discovered models
  • Read XMI models as JSON (root-first, containment-expanded)
  • Lightweight reference handling using _ref

Model Editing write

  • Create model instances
  • Delete model elements
  • ...

Interoperability integration

  • Tool-agnostic REST layer on top of EMF
  • Works well with low-code flows (n8n) and AI tools (MCP)
  • Supports heterogeneous modeling platforms through a uniform API

Operational Readiness ops

  • Swagger/OpenAPI for fast testing
  • Stable JSON responses for dashboards and clients
  • Repository-based loading (Ecore + XMI scanning patterns)

API Endpoints patterns

Note: Endpoint paths can vary depending on your current controllers and dynamic API generation. Use Swagger as the source of truth; the examples below are copy-ready patterns you can adapt immediately.

Metamodel & Model discovery

  • GET /api/v1/metamodels — list of metamodels
  • GET /api/v1/repository/list — list available metamodels and their corresponding models
  • GET /api/v1/metamodels/{packageName}/structure — list the structure of the metamodel

Read model content

  • GET /api/v1/models/{modelFileName}/content — Read the content of your model (xmi file)
  • GET /api/v1/models/{modelFileName}/{packageName}/{className}/instances — Get an instance of a class

Create & insert objects

  • POST /api/v1/models/{modelFileName}/{parentPackage}/{parentClass}/children — insert child into parent container (pattern)
  • POST /api/v1/models/{modelFileName}/{packageName}/{className}/instances — Create an instance of a class

Read and Edit Metamodel

  • POST /api/v1/metamodels/{packageName}/class — Create an EClass
  • POST /api/v1/metamodels/{packageName}/{className}/attribute — Create an EAttribute
  • GET /api/v1/metamodels/{packageName}/structure — GET the structure of the metamodel

Core Workflows

Workflow A — Browse & Inspect

  • Call discovery endpoints to find packages and models
  • Read a model as hierarchical JSON
  • Identify containment references where new objects can be added

Workflow B — Insert a new object safely

  • Select the parent by class + attribute filter
  • Create the child object with attribute values
  • Attach it via a specific containment reference (e.g., members, devices)
  • Save back to XMI

Insert an object into a container (example payload pattern)
